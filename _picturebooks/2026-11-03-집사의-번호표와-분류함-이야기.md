<section>
  <h2>1. 번호표 붙이기 — 누가, 언제 번호를 매길까</h2>
  <p>창고에 새 물건이 들어오면 번호표가 필요해요. 그런데 "누가 번호를 매기는지", "언제 번호를 알게 되는지"가 방식마다 달라요.</p>
  <div class="pic">
  <svg viewBox="0 0 760 230" role="img" aria-label="IDENTITY는 넣자마자 번호를 받고, SEQUENCE는 번호표 뽑는 기계에서 미리 받아온다">
    <rect x="20" y="30" width="340" height="170" rx="16" class="sun-bg"/>
    <text x="190" y="60" text-anchor="middle" class="t-b">IDENTITY</text>
    <text x="190" y="84" text-anchor="middle" class="t-s">창고(DB)가 번호를 직접 매겨요</text>
    <text x="190" y="108" text-anchor="middle" class="t-s">(MySQL의 AUTO_INCREMENT)</text>
    <text x="190" y="136" text-anchor="middle" class="t-c">persist() → 바로 INSERT!</text>
    <text x="190" y="158" text-anchor="middle" class="t-s">넣자마자 번호를 알 수 있어요</text>
    <text x="190" y="180" text-anchor="middle" class="t-s">(할 일 목록에 못 쌓아둬요)</text>
    <rect x="400" y="30" width="340" height="170" rx="16" class="leaf-bg"/>
    <text x="570" y="60" text-anchor="middle" class="t-b">SEQUENCE</text>
    <text x="570" y="84" text-anchor="middle" class="t-s">번호표 뽑는 기계(DB 시퀀스)에서</text>
    <text x="570" y="106" text-anchor="middle" class="t-s">번호만 먼저 뽑아와요</text>
    <text x="570" y="134" text-anchor="middle" class="t-c">persist() → 번호만 받고 대기</text>
    <text x="570" y="156" text-anchor="middle" class="t-s">실제 INSERT는 commit(결재) 때</text>
    <text x="570" y="178" text-anchor="middle" class="t-s">(할 일 목록에 쌓아둘 수 있어요)</text>
  </svg>
  </div>
  <p class="cap">어제 배운 "할 일 목록(쓰기 지연 SQL 저장소)" 기억나요? IDENTITY 방식은 번호를 알려면 꼭 창고에 먼저 다녀와야 해서, persist()하자마자 바로 INSERT가 나가요. 이것 말고도 키 생성 전용 테이블을 쓰는 TABLE, DB에 맞춰 자동으로 골라주는 AUTO 방식도 있어요.</p>
</section>

<section>
  <h2>2. 설명 카드 쓰기 — 이 상자는 어떻게 생겼나요</h2>
  <p>상자(필드)마다 "이 칸은 비워두면 안 돼요", "이 칸은 겹치면 안 돼요" 같은 설명 카드를 붙여요. 이 카드에 적힌 대로 집사가 창고 상자(테이블)를 만들어요.</p>
  <div class="pic">
  <svg viewBox="0 0 760 210" role="img" aria-label="Column 속성으로 상자 설명 카드를 적는다">
    <rect x="30" y="30" width="700" height="160" rx="16" class="sky-bg"/>
    <text x="380" y="58" text-anchor="middle" class="t-b">🏷 member_id 상자 설명 카드</text>
    <rect x="60" y="76" width="150" height="40" rx="8" class="paper bd"/>
    <text x="135" y="100" text-anchor="middle" class="t-c">name</text>
    <rect x="224" y="76" width="150" height="40" rx="8" class="paper bd"/>
    <text x="299" y="100" text-anchor="middle" class="t-c">nullable=false</text>
    <rect x="388" y="76" width="150" height="40" rx="8" class="paper bd"/>
    <text x="463" y="100" text-anchor="middle" class="t-c">unique=true</text>
    <rect x="552" y="76" width="150" height="40" rx="8" class="paper bd"/>
    <text x="627" y="100" text-anchor="middle" class="t-c">length / 정의</text>
    <text x="135" y="140" text-anchor="middle" class="t-s">컬럼 이름</text>
    <text x="299" y="140" text-anchor="middle" class="t-s">비워두면 안 돼요</text>
    <text x="463" y="140" text-anchor="middle" class="t-s">겹치면 안 돼요</text>
    <text x="627" y="140" text-anchor="middle" class="t-s">글자 길이·정의</text>
    <text x="380" y="172" text-anchor="middle" class="t-s">이 카드는 집사가 창고 상자를 "처음 만들 때(DDL)" 사용해요</text>
  </svg>
  </div>
  <p class="cap">예를 들어 <code>@Column(name = "member_id", nullable = false, unique = true, columnDefinition = "varchar(10)")</code>라고 쓰면, 집사는 "member_id 칸은 10자짜리 문자열이고, 비어있으면 안 되고, 다른 회원과 겹치면 안 돼요"라는 설명 카드대로 창고 상자를 만들어요.</p>
</section>

<section>
  <h2>3. 날짜 도장 찍기 — 날짜만? 시간까지?</h2>
  <p>회원이 가입한 날을 기록할 때, 날짜만 찍는 도장과 날짜+시간까지 찍는 도장이 따로 있어요.</p>

    <text x="560" y="114" text-anchor="middle" class="t-s">날짜 + 시간까지 쿵!</text>

</section>

<section>
  <h2>4. 정해진 분류함에만 넣기 — enum과 @Enumerated</h2>
  <p>회원의 권한은 "일반회원" 아니면 "관리자" 둘 중 하나뿐이에요. 이렇게 <b>정해진 값만</b> 쓰게 만드는 게 enum이에요. 그런데 이걸 창고에 숫자로 적어둘지, 글자로 적어둘지가 또 중요해요.</p>
  <div class="pic">
  <svg viewBox="0 0 760 220" role="img" aria-label="ORDINAL은 숫자로, STRING은 글자로 저장한다">
    <rect x="20" y="30" width="340" height="160" rx="16" class="berry-bg"/>
    <text x="190" y="60" text-anchor="middle" class="t-b">ORDINAL (숫자표)</text>
    <text x="190" y="88" text-anchor="middle" class="t-c">ROLE_MEMBER → 0</text>
    <text x="190" y="110" text-anchor="middle" class="t-c">ROLE_ADMIN → 1</text>
    <text x="190" y="138" text-anchor="middle" class="t-s">나중에 분류 순서를 바꾸면</text>
    <text x="190" y="158" text-anchor="middle" class="t-s">숫자 의미가 뒤죽박죽! 😵</text>
    <rect x="400" y="30" width="340" height="160" rx="16" class="leaf-bg"/>
    <text x="570" y="60" text-anchor="middle" class="t-b">STRING (이름표) ✅</text>
    <text x="570" y="88" text-anchor="middle" class="t-c">ROLE_MEMBER → "ROLE_MEMBER"</text>
    <text x="570" y="110" text-anchor="middle" class="t-c">ROLE_ADMIN → "ROLE_ADMIN"</text>
    <text x="570" y="138" text-anchor="middle" class="t-s">이름 그대로 적어두니</text>
    <text x="570" y="158" text-anchor="middle" class="t-s">순서가 바뀌어도 안전해요</text>
  </svg>
  </div>
  <p class="cap">그래서 실무에서는 <code>@Enumerated(EnumType.STRING)</code>을 권장해요. 글자가 숫자보다 자리를 조금 더 차지하지만, 나중에 분류 종류가 늘거나 순서가 바뀌어도 안전한 게 훨씬 중요하거든요.</p>
</section>

<section>
  <h2>6. 읽기만 할 땐 사진을 안 찍어도 돼요</h2>
  <p>어제 집사는 물건을 꺼낼 때마다 몰래 사진(스냅샷)을 찍어뒀다가, 나중에 바뀐 점이 있으면 알아서 수정 쪽지를 만든다고 했었죠? 그런데 <b>조회만 하고 끝낼 거라면</b>, 애초에 사진을 찍어둘 필요가 없어요.</p>
  <div class="pic">
  <svg viewBox="0 0 760 170" role="img" aria-label="readOnly 트랜잭션은 스냅샷을 찍지 않아 더 가볍다">
    <rect x="40" y="30" width="320" height="110" rx="16" class="sky-bg"/>
    <text x="200" y="62" text-anchor="middle" class="t-b">읽고 쓰는 집사</text>
    <text x="200" y="88" text-anchor="middle" class="t-c">@Transactional</text>
    <text x="200" y="112" text-anchor="middle" class="t-s">혹시 몰라 사진도 찍어둬요</text>
    <rect x="400" y="30" width="320" height="110" rx="16" class="leaf-bg"/>
    <text x="560" y="62" text-anchor="middle" class="t-b">읽기만 하는 집사</text>
    <text x="560" y="88" text-anchor="middle" class="t-c">@Transactional(readOnly = true)</text>
    <text x="560" y="112" text-anchor="middle" class="t-s">사진 안 찍어서 더 가벼워요</text>
  </svg>
  </div>
  <p class="cap">조회만 하는 메서드에 <code>readOnly = true</code>를 붙이면, 집사는 "이건 바뀔 일이 없으니 사진 안 찍어도 돼" 하고 불필요한 변경 감지(Dirty Checking) 작업을 건너뛰어요.</p>
</section>

<div class="dict">
  <div class="term"><b>@GeneratedValue</b><small>GenerationType</small>번호표를 누가·언제 만드는지 정해요. IDENTITY는 넣자마자, SEQUENCE는 미리 뽑아둬요.</div>
  <div class="term"><b>@Column</b><small>name/nullable/unique/length</small>상자 하나하나에 붙이는 설명 카드예요. 집사가 창고 상자를 만들 때 이 카드를 봐요.</div>
  <div class="term"><b>@Enumerated(STRING)</b><small>EnumType</small>정해진 분류값을 숫자 대신 이름 글자로 저장해서 나중에도 안전하게 해요.</div>
  <div class="term"><b>Controller → Service → Repository</b><small>계층 구조</small>손님 맞이 → 규칙·결재 관리 → 실제 창고 메모장 다루기로 일을 나눠요.</div>
  <div class="term"><b>@Transactional(readOnly=true)</b><small>읽기 전용 트랜잭션</small>조회만 할 땐 사진(스냅샷)을 안 찍어서 더 가볍게 동작해요.</div>
</div>

<div class="sum">
  <b style="font-family:var(--f-display);font-weight:400;font-size:22px">한 줄 정리</b><br>
  새 회원이 들어올 땐 집사가 <code>@GeneratedValue</code>로 번호표를 붙이고, <code>@Column</code>으로 상자 설명 카드를 쓰고, <code>@Enumerated(STRING)</code>으로 정해진 분류함에만 안전하게 넣어요. 이 모든 일은 Controller·Service·Repository라는 여러 집사가 나눠서 하고, 조회만 할 땐 <code>readOnly=true</code>로 더 가볍게 움직여요.
