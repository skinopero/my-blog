어제 글자·목록·표·영역 태그를 배웠고, 오늘은 이미지·미디어·하이퍼링크·폼까지 이어서 배웠다. 특히 폼(form)은 사용자 입력을 서버로 보내는 시작점이라 가장 분량이 많았다.

## 1. 이미지 태그 — src·alt, 고정 크기와 가변 크기

```html
<img src="sample/image/city1.PNG" alt="도시">
```

- `src` — 어떤 이미지 파일을 보여줄지 경로를 적는 속성
- `alt` — 그림을 못 읽거나 화면 읽기 프로그램을 쓸 때 대신 읽어주는 텍스트 (꾸미기용이 아니라 **꼭 채워야 하는** 속성)

```html
<!-- 고정 크기: 화면이 커져도 작아져도 그대로 -->
<img src="..." width="200px" height="100px">
<!-- 가변 크기: 화면 크기에 비례해서 변함 -->
<img src="..." width="20%" height="100px">
```

`width`에 `px`(고정)를 쓰느냐 `%`(가변)를 쓰느냐에 따라, 화면 크기가 바뀔 때 이미지가 반응하는 방식이 달라진다는 걸 확인했다.

## 2. 미디어 태그 — audio·video

```html
<audio src="sample/audio/major.mp3" controls loop>뮤직 큐</audio>
<video src="sample/video/video1.mp4" controls></video>
```

`controls` 속성을 붙이면 재생/정지/볼륨 같은 기본 컨트롤러가 화면에 나타나고, `loop`를 붙이면 반복 재생된다.

## 3. 하이퍼링크 태그 — a 태그의 세 가지 쓰임

```html
<!-- 1. 텍스트로 이동 -->
<a href="02_목록관련태그.html">목록 관련 태그</a>

<!-- 2. target 속성으로 새 탭/같은 탭 지정 -->
<a href="https://skinopero.github.io/my-blog/" target="_blank">블로그</a>

<!-- 3. 이미지를 눌러서 이동 (a 태그 안에 img 태그) -->
<a href="https://www.naver.com">
  <img src="sample/image/strawberry.png">
</a>
```

`target="_blank"`는 새 탭에서, `target="_self"`(기본값)는 같은 탭에서 열린다는 차이를 확인했다. 그리고 `a`와 `img`를 겹쳐 쓰면 "이미지를 클릭해서 이동"하는 링크도 만들 수 있었다 — `a`가 부모 태그, `img`가 자식 태그로 들어가는 구조다.

흥미로웠던 건 **한 페이지 안에서 점프하는 앵커**였다.

```html
<ul>
  <li><a href="#index1">목차1</a></li>
  <li><a href="#index2">목차2</a></li>
</ul>
...
<h4 id="index1">목차 1번 영역</h4>
...
<h4 id="index2">목차 2번 영역</h4>
```

다섯 살 아이에게 설명한다면: "책 목차에서 '2장'을 누르면 새 책을 사는 게 아니라, 지금 읽던 책의 2장 페이지로 바로 넘어가잖아. `href="#index2"`도 똑같아. 새 페이지로 가는 게 아니라, `id="index2"`라고 이름표 붙여둔 곳으로 화면만 쓱 이동시켜주는 거야."

![href에 #id값을 넣으면 새 페이지로 이동하는 게 아니라, 같은 페이지 안에서 그 id를 가진 태그 위치로 화면이 이동한다는 그림]({{ site.baseurl }}/assets/images/2026-09-02-anchor-jump.svg)

`id` 속성은 그 태그의 고유한 이름표 역할을 해서, `href="#id값"`을 만나면 브라우저가 같은 `id`를 가진 태그를 찾아 그 위치로 화면을 이동시킨다.

## 4. 폼 태그 — 사용자 입력을 서버로 보내는 양식

```html
<form action="search" method="post">
  <label>검색 할 내용 : </label>
  <input type="text" name="search" required>
  <button type="submit">검색</button>
</form>
```

`form`의 핵심 속성 두 가지를 배웠다.

| 속성 | 의미 |
|---|---|
| `action` | 입력된 값을 전송받을 서버 주소 |
| `method` | 전송 방식 — `get`(URL에 데이터 노출) / `post`(URL에 데이터 감춰짐) |

`input` 태그는 `type`에 따라 완전히 다른 입력 UI가 된다는 걸 하나씩 확인했다.

| `type` | 용도 |
|---|---|
| `text` | 한 줄 텍스트 입력 |
| `password` | 입력값이 가려지는 비밀번호 입력 |
| `number`, `range` | 숫자 입력, 슬라이더 |
| `date`, `time`, `datetime-local` 등 | 날짜·시간 입력 |
| `radio` | 여러 개 중 **하나만** 선택 (같은 `name`으로 그룹 묶기) |
| `checkbox` | 여러 개 **동시에** 선택 가능 |
| `color`, `file`, `hidden` | 색상 선택, 파일 첨부, 화면에 안 보이는 값 전달 |

`<label for="userId">`와 `<input id="userId">`를 `for`/`id`로 짝지어주면, 라벨 텍스트를 클릭해도 그 입력 칸에 포커스가 가는 것도 확인했다. `<select>`/`<option>`으로 드롭다운 목록을 만들 수 있고, `<textarea>`는 `input type="text"`와 달리 여러 줄을 입력할 수 있다는 차이도 짚었다.

```mermaid

    U[사용자가 폼에 값 입력] --> M{method?}
```

## 오늘의 정리

이미지·미디어 태그는 `src`로 무엇을 보여줄지만 정하면 되는 비교적 단순한 태그였고, 하이퍼링크는 `href` 하나로 다른 페이지로도, 같은 페이지 안으로도(`#id`) 이동할 수 있었다. 폼은 `action`(어디로)과 `method`(어떻게)만 정하면, 그 안의 다양한 `input type`으로 원하는 형태의 입력을 받을 수 있는 구조였다.

## 더 학습하면 좋은 개념

- **GET과 POST의 실제 차이** — 오늘은 "URL에 보이는지 아닌지"만 배웠는데, 10월에 서블릿을 배우면서 doGet/doPost가 이걸 어떻게 처리하는지 더 깊이 이어진다.
- **폼 유효성 검사(Validation)** — 오늘 쓴 `required` 속성처럼, HTML만으로도 간단한 입력 검증을 할 수 있다. `pattern`, `min`/`max` 같은 다른 속성도 더 찾아보면 좋다.
- **반응형 이미지(`srcset`, `picture`)** — 오늘은 `width`를 `%`로 줘서 가변 크기를 만들었는데, 화면 크기별로 아예 다른 이미지 파일을 보여주는 더 정교한 방법도 있다.
