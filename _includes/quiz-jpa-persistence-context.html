1JDBC로 같은 메뉴를 두 번 조회(findMenuByMenuCode)하면 menu1 == menu2는 왜 false일까?
JDBC를 직접 쓰면 조회할 때마다 새 객체를 만들어 담기 때문에, 같은 행을 조회해도 서로 다른 객체(동일성 보장 안 됨)가 된다.
2JPA(Java Persistence API)는 한마디로 무엇일까?
JPA는 Object Relational Mapping(ORM) 기술 표준으로, 자바 객체(Entity)와 DB 테이블을 자동으로 연결해준다.
3@ManyToOne의 기본 페치(fetch) 전략은?
@ManyToOne의 기본값은 EAGER(즉시 로딩)라서, 메뉴를 조회하면 연관된 Category까지 자동으로 함께 로딩된다.
4같은 트랜잭션 안에서 같은 PK로 manager.find()를 두 번 호출하면?
영속성 컨텍스트는 한 번 조회한 엔티티를 기억해두고(1차 캐시), 같은 트랜잭션 안에서 또 조회하면 DB에 가지 않고 그 객체를 그대로 돌려준다 — 그래서 동일성이 보장된다.
5manager.persist(menu)를 호출한 직후, DB에는 언제 실제로 INSERT가 반영될까?
엔티티 매니저는 CUD 작업을 바로 DB에 보내지 않고 쓰기 지연 SQL 저장소에 모아둔다. transaction.commit()이 호출되면 flush가 자동 실행되어 쌓인 SQL이 한 번에 전송된다.
6EntityManager에 update() 메서드가 따로 없는 이유는?
영속성 컨텍스트는 조회 시점의 스냅샷을 보관해두고, commit 시점에 현재 엔티티 상태와 비교(변경 감지)해서 달라진 점이 있으면 자동으로 UPDATE 쿼리를 만든다. 그래서 setter로 값만 바꾸면 된다.
7manager.remove(menu)를 호출한 직후 바로 같은 메뉴를 조회해보면?
삭제도 등록과 마찬가지로 commit() 시점에 실제 DELETE 쿼리가 DB로 전송되므로, commit 전이라면 DB에는 아직 데이터가 남아있을 수 있다.
8application.yaml에서 hibernate.ddl-auto: none은 무슨 뜻일까?
ddl-auto는 create(새로 생성), create-drop(생성 후 종료시 삭제), update(변경사항 반영), none(자동 반영 없음, DDL 스크립트로만 관리) 중 하나로 설정한다.
