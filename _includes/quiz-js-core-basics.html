1const shop = "원티드 식당"; shop = 1;을 실행하면?
const는 재할당이 불가능하다. 값을 다시 바꾸려면 let을 쓴다. let은 test = 1; test = "문자열";처럼 타입이 달라져도 에러가 나지 않는다.
2JavaScript에서 변수의 타입은 언제 정해질까?
자료형을 신경 쓰지 않고 선언할 수 있는 것이 장점이지만, 값이 언제든 다른 타입으로 바뀔 수 있어서 값을 확인하기 전에는 타입을 확신할 수 없는 것이 단점이다. 현재 타입은 typeof로 확인한다.
3typeof null과 typeof []의 결과는 각각?
실습에서 확인한 결과다. null, {}, [] 모두 "object"로 나오고, 함수만 "function"으로 나온다.
4함수를 선언문보다 앞에서 호출했을 때 정상 동작하는 경우는? (호이스팅)
함수 선언문은 런타임 이전에 JS 엔진이 먼저 인식하므로 앞에서 호출할 수 있다. 함수 표현식은 변수에 값이 할당되는 줄에 도달해야 쓸 수 있어서 앞에서 부르면 에러가 난다.
5화살표 함수에서 중괄호와 return을 생략할 수 없는 경우는?
본문이 식 하나면 () => 값처럼 줄일 수 있지만, 코드가 많으면 생략할 수 없다. 매개변수가 1개일 때는 소괄호도 생략할 수 있다.
6['제육', '떡볶이', 1, {name:'hi'}, function(){}]처럼 여러 타입을 섞은 배열은?
Java 배열과 달리 JavaScript 배열은 타입 제한이 없다. 실습 파일 첫 주석은 "같은 자료형만"이라고 적혀 있지만 바로 아래 코드가 보여주는 실제 동작은 반대다.
7map과 filter의 반환값을 맞게 설명한 것은?
forEach는 반환값이 없고, map은 변환 결과의 새 배열, filter는 조건에 맞는 요소만 모은 새 배열이다. 각 단계가 새 배열을 만들기 때문에 이어서 쓸 수 있다.
81 == '1'과 1 === '1'의 결과는 각각?
동적 타입 언어에서는 ==가 예상 밖의 true를 만들 수 있어서 비교는 ===를 쓰는 것이 안전하다.
