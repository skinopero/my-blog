1useEffect가 하는 일을 가장 정확하게 설명한 것은?
API 응답이 언제 올지 알 수 없으므로 컴포넌트를 먼저 띄우고, 그 이후에 요청한 뒤 응답이 오는 대로 state에 넣어 다시 렌더링한다.
2의존성 배열을 생략한 useEffect는 언제 실행되는가?
생략 = 렌더링마다, [] = 마운트 시 한 번, [값] = 마운트 + 값이 바뀔 때. 생략한 effect는 state가 바뀌어 리렌더링될 때마다 실행된다.
3화면이 처음 나타날 때 회원 목록 API를 한 번만 호출하려면?
빈 배열은 마운트 시 한 번만 실행한다. 배열을 빼거나 [users]처럼 응답으로 바뀌는 state를 넣으면 응답 → state 변경 → 리렌더링 → 다시 요청이 반복될 수 있다.
4useEffect(async () => {...})처럼 콜백에 바로 async를 붙이지 않고, 안에 async function을 따로 만들어 호출하는 이유는?
effect 콜백은 아무것도 반환하지 않거나 정리(clean-up) 함수를 반환해야 한다. 그래서 안에 async function loadUsers()를 만들고 바로 호출한다. 안쪽 함수에서는 await를 자유롭게 쓸 수 있다.
5fetch 코드에서 await를 두 번 쓰는 이유로 맞는 것은?
const res = await fetch(url)로 응답을 받고, const json = await res.json()으로 본문을 진짜 객체로 바꾼다. 둘 다 시간이 걸리는 작업이라 각각 Promise를 기다린다.
6useState([])로 시작하는 users에 대해 if (users.length === 0) return <h3>불러오는 중...</h3>를 두는 이유는?
응답이 도착하기 전 첫 렌더링에서는 데이터가 없다. 이 구간에 안내 문구를 보여주면 빈 화면이나 데이터 접근 에러를 막고, 응답이 오면 setUsers로 리렌더링되며 목록이 그려진다.
7effect에서 return () => {...}로 반환한 정리(clean-up) 함수는 언제 실행되는가?
타이머처럼 effect에서 시작한 작업은 정리 함수에서 끝내야 한다. 안 그러면 컴포넌트가 사라진 뒤에도 계속 동작한다(예: 숨긴 뒤에도 tick이 계속 출력).
8포켓몬 도감에서 이전·다음 버튼을 빠르게 눌렀을 때 ignore 플래그가 막아주는 문제는?
effect가 실행될 때마다 ignore가 새로 만들어지고, id가 바뀌면 정리 함수가 이전 effect의 ignore를 true로 바꾼다. 그래서 늦게 온 옛날 응답은 setPokemon을 호출하지 못한다.
