1어제 CDN 방식과 비교한 오늘 Vite 프로젝트의 차이로 맞는 것은?
CDN 방식은 브라우저에서 Babel로 변환했지만, Vite는 빌드 단계에서 변환한다. 의존성은 package.json으로 관리하고, 시작점은 src/main.jsx다.
2export default와 이름 붙인 export를 가져오는 방법으로 맞게 짝지은 것은?
default는 중괄호 없이 이름을 마음대로 붙여 가져오고 파일당 1개만 가능하다. named export는 {}로 가져오고, 이름이 같아야 하며 한 파일에서 여러 개를 내보낼 수 있다.
3라우팅에서 BrowserRouter, Routes, Route의 역할을 맞게 설명한 것은?
BrowserRouter는 최상위, Routes는 Route들의 부모, Route는 path와 element를 연결한다.
4<Route path="/" element={<Layout/>}> 안에 Route를 또 넣는 중첩 구조의 목적은?
공통 틀(메뉴)은 그대로 두고, 안쪽 컴포넌트만 주소에 맞게 바뀌게 하는 구조다. 모든 페이지에 같은 메뉴를 복사해서 넣을 필요가 없다.
5Layout 안의 <Outlet/>은 무엇을 하는 자리일까?
메뉴를 클릭해도 Navbar는 그대로이고 Outlet 부분만 바뀐다.
6<a href>와 <Link>/<NavLink>의 차이로 맞는 것은?
NavLink는 Link와 같고, 현재 주소와 일치하면 isActive가 true가 되어 스타일을 바꿀 수 있다.
7style={({isActive}) => isActive ? {...} : undefined}처럼 함수를 넘기면 어떤 일이 생길까?
NavLink의 isActive로 지금 어느 메뉴에 있는지 알려준다. 오늘 실습에서는 활성 메뉴에 주황색 배경과 흰색 글씨를 적용했다.
8CSS 모듈(Navbar.module.css)을 쓰는 이유는?
파일명을 이름.module.css로 쓰고 객체(styles)로 import해서 className={styles.nav}처럼 쓴다. 일반 CSS는 페이지 전체에 적용된다.
