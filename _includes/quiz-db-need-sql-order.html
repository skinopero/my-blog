1JVM 메모리 세 구역 중 static 변수가 머무는 곳은? (입문 단계 기준)
Method Area에는 클래스 정보와 static 변수가 저장돼. (JDK 8+ HotSpot에서는 내부적으로 Heap 쪽으로 옮겨졌지만, 입문 단계에서는 Method Area로 묶어서 설명해.)
2메서드 안에서 선언한 지역변수는 언제 사라질까?
지역변수는 Stack에 쌓였다가, 그 메서드 호출이 끝나는 순간 함께 사라져.
3회원 목록을 List<Member>(Heap)에만 저장하고 서버를 재시작하면?
RAM은 전원이 꺼지면 내용이 지워지는 휘발성 메모리라서, JVM 프로세스가 끝나면 Heap에 있던 모든 객체가 함께 사라져.
4회원을 파일(members.txt)에 저장해도 여전히 해결되지 않는 문제는?
파일은 영속성(꺼져도 안 사라짐)만 해결해줄 뿐, "읽고-판단하고-쓰는" 사이에 다른 요청이 끼어드는 동시성 문제는 막지 못해.
5계좌이체 도중 서버가 멈춰도 "전부 성공 아니면 전부 취소"를 보장하는 DB 기능은?
트랜잭션은 START TRANSACTION ~ COMMIT/ROLLBACK으로 여러 작업을 하나의 단위로 묶어서, 중간에 실패하면 전부 되돌려.
6SQL을 쓸 때는 1번째인데, 실제 처리 순서는 5번째인 절은?
작성 순서는 SELECT가 1번이지만, 실제 실행 순서는 FROM(1)-WHERE(2)-GROUP BY(3)-HAVING(4)-SELECT(5)-ORDER BY(6)-LIMIT(7)이라 SELECT가 가장 멀리 이동해.
7SELECT score*1.1 AS bonus FROM scores WHERE bonus >= 90이 에러인 이유는?
WHERE(2번)가 처리되는 시점엔 SELECT(5번)가 아직 실행되지 않아서, SELECT에서 만든 별칭 bonus를 WHERE가 알 수 없어.
8ORDER BY avg_score DESC처럼 ORDER BY에서는 SELECT 별칭을 써도 되는 이유는?
실행 순서상 ORDER BY는 SELECT 뒤에 처리되기 때문에, SELECT가 만든 별칭이 이미 존재하는 상태라 그대로 쓸 수 있어.
