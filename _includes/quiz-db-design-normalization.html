1주소(시/구/동)처럼 두 개 이상의 하위 속성으로 나눌 수 있는 속성은?
복합 속성은 두 개 이상의 하위 속성으로 나눌 수 있는 속성이야. 제1정규형에 따라 한 칸에는 값이 하나만 들어가야 하므로, 복합 속성은 필요에 따라 하위 속성으로 쪼개.
2후보키 중 기본키로 선택되지 않고 남은 키는 어떻게 관리할까?
대체키(Alternate Key)는 기본키로 선택되지 않은 나머지 후보키이고, UNIQUE 제약조건으로 유일성만 관리해.
3회원 이메일이 유일한데도 기본키로 부적절한 가장 큰 이유는?
기본키 선정 기준 중 불변성(Stability) — 한 번 정해진 값은 시간이 지나도 바뀌지 않아야 한다 — 을 이메일이 어긴다는 게 핵심이야. 게다가 개인정보라 보호 문제도 있어서, 대체키로만 UNIQUE 관리해.
4학생·학과·과목·수강이 한 표에 섞여 있는데, 학과 전화번호가 바뀌어서 일부 행만 고치면 생기는 문제는?
같은 사실(학과 전화번호)이 여러 행에 중복돼 있어서, 일부만 고치면 서로 모순되는 게 갱신 이상(Update Anomaly)이야.
5수강생이 한 명도 없는 새 과목을 등록하고 싶은데, 수강신청 표에는 학생 정보가 없으면 행을 만들 수 없다. 이건 어떤 이상 현상?
넣고 싶은 정보(새 과목)가 있는데, 관계없는 정보(수강생)가 없어서 넣을 수 없는 게 삽입 이상(Insertion Anomaly)이야.
62040년에 끝나는 구독 만료 일시를 저장하기에 적절한 컬럼 타입은?
TIMESTAMP는 1970~2038-01-19까지만 표현 가능해서 2040년 값은 저장 자체가 거부돼. DATETIME은 1000~9999년까지 표현할 수 있어서 미래 날짜에 안전해.
7외래키에 ON DELETE SET NULL을 쓰려면 그 외래키 컬럼은 어떻게 정의해야 할까?
SET NULL은 부모가 삭제/변경되면 자식의 외래키를 NULL로 바꾸는 옵션이라서, 그 컬럼이 NOT NULL이면 테이블 생성 자체가 실패해.
8MySQL InnoDB에서 표준 SQL의 SET DEFAULT 참조 무결성 옵션을 쓰면?
InnoDB는 SET DEFAULT를 지원하지 않아서, 문법은 파싱되더라도 테이블 생성 자체가 거부돼. CASCADE/SET NULL/RESTRICT 세 가지만 실제로 쓸 수 있어.
