1서블릿이 브라우저에 HTML 응답을 써서 보낼 때 사용하는 객체는?
resp.getWriter()로 PrintWriter를 얻어서 HTML 문자열을 그대로 써서 내려보낼 수 있어.
2web.xml에서 404·500 에러가 발생했을 때 지정한 서블릿으로 보내는 설정은?
<error-page>에 에러 코드와 location을 지정해두면, 해당 에러 발생 시 그 서블릿으로 요청이 넘어가.
3resp.sendError(404, ...)를 호출하면 내부적으로 어떤 방식으로 에러 페이지에 도달할까?
컨테이너가 web.xml의 <error-page> 설정을 보고, 원래 서블릿이 응답한 것처럼 내부적으로 forward 방식으로 에러 처리 서블릿에 넘겨.
4req.getAttribute("jakarta.servlet.error.status_code")로 가져오는 값은?
에러 처리용 서블릿은 이 속성으로 몇 번 에러가 발생했는지(404, 500 등) 알 수 있어.
5forward 방식에서 원래 서블릿과 위임받은 서블릿의 관계는?
forward는 req·resp 객체를 그대로 공유해서, req.setAttribute()로 넘긴 값을 다음 서블릿이 req.getAttribute()로 바로 받을 수 있어.
6forward가 일어난 뒤, 클라이언트 브라우저의 주소창 URL은?
forward는 서버 내부에서만 일어나는 일이라, 클라이언트는 URL 변화 없이 그냥 응답만 받게 돼.
7forward 방식을 INSERT·UPDATE·DELETE 처리에 쓰면 안 되는 이유는?
forward는 URL이 바뀌지 않기 때문에, 사용자가 결과 화면에서 새로고침하면 동일한 요청(INSERT 등)이 그대로 다시 실행될 위험이 있어.
8다른 서블릿으로 forward하기 위해 객체를 얻는 메서드는?
RequestDispatcher rd = req.getRequestDispatcher("/print"); rd.forward(req, resp);처럼 사용해.
