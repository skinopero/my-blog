1화면 input의 name과 @RequestParam 변수명이 일치하지 않으면 어떻게 될까?
필수 파라미터를 이름으로 찾지 못하면 바인딩 단계에서 실패해 400 Bad Request가 난다. 이름이 다르면 @RequestParam("name")처럼 명시해야 한다.
2여러 input 값을 DTO 객체 하나로 묶어서 받고 싶을 때 쓰는 어노테이션은?
@ModelAttribute는 input의 name과 일치하는 DTO 필드에 값을 자동으로 묶어 넣어준다. 값을 하나씩 꺼낼 땐 @RequestParam을 쓴다.
3컨트롤러가 접두사 없이 문자열 "result"만 리턴하면 어떻게 동작할까?
String 반환은 view 경로로 해석되어 forward가 기본이고, 리다이렉트는 "redirect:/"처럼 접두사를 명시해야 한다.
4redirect 후에도 값을 유지하려면 Model 대신 무엇을 써야 할까?
redirect는 브라우저가 요청을 두 번 보내므로 첫 요청의 Model 값은 두 번째 요청에서 사라진다. FlashAttribute는 리다이렉트된 다음 요청까지 값을 전달해준다.
5"컨트롤러 전에 유효성 에러 발생"이 의미하는 것은?
@RequestParam/@ModelAttribute 바인딩은 핸들러 메서드 호출 전에 처리된다. 타입·이름이 안 맞으면 메서드 코드가 실행되지 않은 채 예외가 던져진다.
6앱 전체의 공통 예외 처리를 한곳에 모으고 싶을 때 쓰는 것은?
@ExceptionHandler는 선언한 컨트롤러에만 적용되고, @ControllerAdvice 클래스 안에 두면 전역으로 적용된다.
7HandlerInterceptor.preHandle()이 false를 반환하면?
preHandle이 true일 때만 다음 단계(컨트롤러)로 진행한다. 권한 체크처럼 요청을 막고 싶을 때 false를 활용한다.
8long startTime = (long) request.getAttribute("startTime");에서 (long) 형변환이 필요한 이유는?
HttpServletRequest.getAttribute()는 Object를 돌려준다. preHandle에서 저장한 시작 시각을 postHandle에서 꺼낼 땐 원래 타입으로 다운캐스팅해야 한다.
