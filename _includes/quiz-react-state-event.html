1props에 대한 설명으로 맞는 것은?
props는 부모→자식으로 내려오는 읽기 전용 값이다. 숫자·배열·함수는 {}로 전달하고, 자식에서 수정하지 않는다.
2<Box>텍스트</Box>처럼 태그 사이에 쓴 내용을 받으려면?
태그 사이의 내용은 props.children으로 전달된다. 구조 분해로 {children}처럼 받으면 편하다.
3일반 변수 let count를 버튼으로 바꿨는데 화면이 그대로인 이유는?
리렌더링은 state의 setter를 호출했을 때 일어난다. 일반 변수는 값만 바뀔 뿐 화면을 다시 그리지 않는다.
4count가 0일 때 setCount(count + 1)을 세 번 호출하면 결과는?
그 렌더링에서 count는 0으로 고정된 스냅샷이라 세 번 모두 0 + 1을 계산한다. state는 핸들러가 끝난 뒤 한 번에 반영된다.
53씩 증가시키려면 어떻게 바꿔야 할까?
함수형 업데이트는 이전 결과를 받아 누적 계산한다. 0→1→2→3으로 이어진다.
6이벤트 연결로 맞는 것은?
카멜 표기법을 쓰고 문자열이 아닌 함수를 전달한다. handle()은 렌더링 중에 바로 실행된다. 컴포넌트의 onClick은 props일 뿐이라 내부 DOM 요소에 다시 연결해야 한다.
7setForm({[e.target.name]: e.target.value})처럼 ...form 없이 쓰면 생기는 일은?
state 객체는 자동으로 병합되지 않고 새 객체로 교체된다. 그래서 ...form으로 기존 값을 복사한 뒤 바뀐 키만 덮어쓴다.
8목록 state에서 항목을 삭제하는 방법으로 알맞은 것은?
원본 배열을 수정하면 React가 변경을 알아채지 못한다. filter로 새 배열을 만들어 setter에 전달한다. key는 index보다 고유한 id가 좋다.
