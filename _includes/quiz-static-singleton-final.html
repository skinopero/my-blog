1static 변수는 언제 초기화되나?
static이 붙은 변수는 객체 생성 시점이 아니라 애플리케이션 시작 시점에 딱 한 번 초기화돼.
2인스턴스 100개를 만들면, static 변수는 몇 개 존재하나?
static 변수는 인스턴스마다 따로 있는 게 아니라, 클래스 전체에 딱 하나만 있고 모든 인스턴스가 그걸 공유해.
3static 변수에 접근하는 올바른 방법은?
static 변수는 인스턴스가 아니라 클래스에 속하기 때문에 클래스명.변수명으로 접근해.
4싱글톤 패턴의 목적은?
리모컨처럼 여러 개 있을 필요 없이 하나만 있으면 되는 경우에, 인스턴스를 1개로 제한해서 공유하는 디자인 패턴이야.
5싱글톤 클래스에서 생성자를 private으로 막는 이유는?
생성자가 private이면 외부에서는 new로 새 인스턴스를 만들 수 없고, 오직 getInstance()로만 받을 수 있어.
6이른 초기화(Eager)와 게으른 초기화(Lazy)의 차이는?
Eager는 private static EagerSingleton eager = new EagerSingleton();처럼 바로 만들고, Lazy는 getInstance()에서 null일 때만 그때 생성해.
7final이 붙은 변수는 초기화 이후 몇 번 더 값을 바꿀 수 있나?
final 변수는 (선언과 동시에, 또는 생성자에서) 딱 한 번만 초기화되고, 그 뒤로는 setter로도 값을 바꿀 수 없어.
8final 변수의 네이밍 관례는?
값이 바뀌지 않는다는 걸 한눈에 알아볼 수 있도록, final 변수는 관례상 대문자와 언더바로 써.
