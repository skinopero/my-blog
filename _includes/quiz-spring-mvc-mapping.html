1클래스에 @RequestMapping("/order/*"), 메서드에 @GetMapping("/regist")를 붙이면 최종 경로는?
클래스 레벨 매핑과 메서드 레벨 매핑은 합쳐져서 최종 요청 경로를 완성해.
2/order/detail/{orderNo}에서 @PathVariable로 꺼내는 값은?
PathVariable은 URL 경로 중간에 끼워진 값을 그대로 꺼내 쓰는 것이야.
3@GetMapping("/regist")은 사실 무엇의 축약형일까?
@GetMapping/@PostMapping은 @RequestMapping에 HTTP 메소드를 지정한 것을 짧게 줄인 표현이야.
4@RequestParam을 쓸 때 가장 조심해야 할 것은?
@RequestParam은 요청 파라미터 이름과 변수명(또는 지정한 이름)이 정확히 일치해야 값을 받아올 수 있어.
5@ModelAttribute MenuDTO menu처럼 쓰면 어떤 일이 일어날까?
@ModelAttribute는 클래스 자료형을 활용해서 여러 입력값을 객체 하나로 묶어주는 어노테이션이야.
6핸들러 메서드가 return "result";를 하면 실제로 찾는 파일은?
ViewResolver가 반환된 문자열에 resources/templates/ 접두사와 .html 접미사를 자동으로 붙여줘.
7문자열 앞에 redirect:를 안 붙이면 Spring의 기본 View 반환 방식은?
Spring에서 View를 반환하는 기본 방식은 forward야. redirect가 필요하면 명시적으로 "redirect:" 접두사를 붙여야 해.
8redirect 후에도 메시지를 딱 한 번만 전달하고 싶을 때 쓰는 것은?
redirect는 새 요청이라 Model 값이 사라지는데, addFlashAttribute()는 세션을 활용해 딱 한 번만 유효한 값을 넘겨줘.
